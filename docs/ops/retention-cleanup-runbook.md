# 保留期清理上线手册（bc:cleanup-retention）

## 0. 一句话

`bc:cleanup-retention` 是**删数据**命令（删数据库记录 + 删云端归档），其 4 条护栏当初是手工推演 8 个场景、从未真实执行过。
**上线前必须在真实数据跑一次 `--dry-run`，确认"将删除 N 条"符合预期，再启用 03:30 调度。**

---

## 1. 前置检查（逐条确认）

```bash
# ① rclone 是否可用（不可用则只清 DB，云端归档变孤儿文件）
command -v rclone

# ② 调度是否已注册（应能看到 bc:cleanup-retention ... dailyAt 03:30）
php artisan schedule:list

# ③ 系统 crontab 是否挂着 schedule:run（没有的话调度根本不触发）
crontab -l | grep schedule:run
```

只有 `websites.retention_days` **非 null 且 > 0** 的启用网站才会被处理，其余一律跳过（护栏 1）。

---

## 2. 执行 dry-run（只统计，不删除）

```bash
cd /path/to/backend
php artisan bc:cleanup-retention --dry-run
```

命令内 dry-run 分支在删除前 `continue`，**不执行 rclone、不删数据库记录**，可以放心跑。

---

## 3. 怎么读输出

每行格式：

```
[dry-run] 网站「X」(id=N, 保留 D 天, 早于 2026-10-07 03:30:00)：将删除 A 条记录 / B 个云端文件
```

结尾汇总：

```
[dry-run] 汇总：涉及网站 X 个, 跳过(retention_days 无效) Y 个, 删除记录 Z 条, 云端删除成功 0 / 失败 0
```

（dry-run 下"云端删除成功/失败"恒为 0，属正常，因为它根本没调 rclone。）

---

## 4. 判读红线 —— 出现任一条，先停下，别启用调度

| # | 现象 | 含义 | 动作 |
|---|---|---|---|
| 1 | 汇总里"跳过(retention_days 无效)"数量很大 | 大量网站没设 retention_days，或设成了 0/负数 → 护栏 1 生效 | 确认是不是配置漏了，而不是以为"已经在清理" |
| 2 | 某网站 A 条数**接近该站备份总数** | 护栏 4 只保"最新 1 条成功"，删完几乎不剩 | 见 §5 已知缺陷；该站若是多备份路径，风险更高 |
| 3 | B（云端文件）**远大于** A（记录数） | 一条记录对应多个 Storage 副本 | 确认 rclone 可用，否则会残留大量孤儿云端文件 |
| 4 | 开头出现 `⚠ 后端容器内未检测到 rclone` | 本次只会清 DB，云端归档删不掉 | **必须先装 rclone 再上线**，否则云端无限累积 |
| 5 | A 很大（≥500） | 护栏 2 每站单次上限 500 条 | 属预期，会分多天删完；不是故障 |

---

## 5. 已知缺陷（本次 dry-run 也掩盖不了，需代码修复）

护栏 4（`CleanupExpiredBackups.php:85-89`）**只按 website 保留"最新 1 条 success"**，
但 `websites` 支持 **`backup_paths`（JSON，多备份路径）**。

**后果**：某网站配了 P1、P2 两个备份目录时，若 P2 的全部超期而 P1 有近期成功，
护栏 4 保住 P1 的最新、**把 P2 的最新一并删掉** → P2 再无可恢复备份。

修复方向：给 `backup_logs` 加来源列（同时解决"self/external 区分"），
护栏 4 改成"每个来源各保留最新 1 条成功"。**该修复实施前，多路径网站建议暂不启用自动清理。**

---

## 6. 确认无误后再启用（建议试点先行）

1. **单站试点**：把其余网站的 `retention_days` 临时置空（护栏 1 会跳过它们），
   只留 1 个备份量小、保留期明确的网站，跑一次**真实清理**（不带 `--dry-run`）。
2. **试点核对**：该站备份数按预期减少 / 云端文件确实消失 / **最近 1 条成功仍在**。
3. **全量启用**：恢复其余网站 `retention_days`，确保 crontab 挂着 `schedule:run`。

---

## 7. 应急

若发现删错了：云端文件已被 rclone 删除，**不可恢复**。
所以 §2 的 dry-run 与 §6 的单站试点不是可选项，是必做项。
