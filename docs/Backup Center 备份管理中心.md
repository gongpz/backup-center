# Backup Center 备份管理中心开发需求文档

## 一、项目名称

**Backup Center（统一备份管理平台）**

---

# 二、项目介绍

开发一个用于管理多个服务器、多网站备份状态的统一管理平台。

该系统不是替代宝塔、AMH等服务器面板的备份功能，而是作为一个独立的备份管理中心。

核心目标：

1. 集中管理多个服务器；
2. 集中管理多个网站；
3. 统一查看备份执行状态；
4. 统一管理远程存储；
5. 统一接收备份结果；
6. 提供失败通知；
7. 降低人工检查多个网站备份状态的成本。

---

# 三、整体设计原则

## 3.1 不接管备份过程

Backup Center 不负责：

* 网站文件打包；
* 数据库导出；
* MySQL操作；
* PHP环境管理；
* Nginx配置管理；
* 网站恢复操作（第一版本）。

网站备份由：

* 宝塔面板；
* AMH面板；
* 用户自定义脚本；

提前生成备份文件。

Backup Center负责：

```
备份文件管理
+
状态监控
+
远程同步
+
通知提醒
+
统一展示
```

# 七、Backup Agent需求

## 7.1 Agent定位

Backup Agent是运行在目标服务器上的轻量客户端。

负责：

* 检测备份目录；
* 判断备份完成；
* 调用Rclone；
* 上传备份；
* 记录日志；
* 上报状态。

---

## 7.2 Agent要求

必须：

* 独立运行；
* 不修改现有环境；
* 不影响网站；
* 不修改宝塔/AMH配置。

安装目录：

```
/opt/backup-agent/
```

结构：

```
backup-agent

├── 程序文件

├── config文件

├── logs目录

└── temp目录
```

---

## 7.3 Agent运行方式

支持Linux Systemd。

例如：

```
systemctl start backup-agent
```

支持：

* 自动启动；
* 自动重启。

# 二十、开发要求

开发时遵循：

1. 模块化设计；
2. 前后端分离；
3. API接口设计；
4. 所有配置后台可完成；
5. 不修改服务器已有环境；
6. 支持后续增加其他面板；
7. 支持后续增加其他通知方式；
8. 支持后续增加其他存储方式。

---

# 最终目标

开发一个：

**免费、轻量、多服务器、多网站、统一管理的个人备份控制中心。**

核心逻辑：

```
宝塔/AMH负责生成备份

↓

Backup Agent负责上传和反馈

↓

Rclone负责连接云存储

↓

Backup Center负责统一管理和通知
```
